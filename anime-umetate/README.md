# アニメ技の埋め立て × TikTok LIVE

配信者が穴（標準 5×5×深さ20＝500ブロック）を下から埋めきったらクリア。1つのサーバーに複数のフィールド（穴）があり、別々のゲームが同時に進みます。待機所でフィールドを選び、ほかの人と最速タイムや対戦で競えます。視聴者のギフトでアニメ・漫画の技が飛んできて、埋めたブロックが崩されます。いいね・シェア・サブスクは埋め立てを助けてくれます。

```
TikTok LIVE ──> tiktok-hub（まとめアプリ、パネル http://127.0.0.1:8800/ の「アニメ埋め立て」タブ、旧 8790）──RCON 25591──> server（Minecraft Java 26.2 バニラ、25590）
                                      └─ OBS 用 http://127.0.0.1:8790/overlay?field=N（そのフィールドの技＋埋め立て％）
```

## 起動
1. `server\start-server.bat`（ポート 25590。ロビーからの転送を受け付ける設定済み）
2. まとめアプリ `..\tiktok-hub`（PC 起動時に自動で起動）のパネル http://127.0.0.1:8800/ の「配信者」ページで、フィールド番号・Minecraft の名前・TikTok の ID を入れて保存（複数の配信を同時につなげます）。
3. Minecraft 26.2 で `localhost:25590` に入る（またはロビーから）。入ると**待機所**に出ます（配信者として名前を割り当てた人は直接自分のフィールドへ）。
4. OBS にブラウザソース `http://127.0.0.1:8790/overlay?field=1`（番号は自分のフィールド。1280×720、背景透明）。

## フィールドと遊び方
| フィールド | 種類 | 場所 |
|---|---|---|
| 1〜4 | 標準 5×5×20（500個） | x=0 / 600 / 1200 / 1800（1 は元の穴と同じ場所） |
| 5〜6 | ミニ 4×4×12（192個） | x=2400 / 3000 |

待機所（x=0, z=-600）。数や種類は `datapack\build.py` の `PRESETS` / `FIELDS` で変えられます。

- **フィールドを選ぶ**: 待機所の看板（光っている台）を右クリック、またはチャットのメニューの［参加］をクリック。コマンドなら `/trigger field set 番号`。メニューを出す: `/trigger menu`。
- 入ったフィールドは空いていればすぐカウントダウンして始まります。同じフィールドに何人でも入れます（協力）。
- **待機所へ戻る**: `/trigger leave`（チャットの［待機所へ］）。誰もいなくなったフィールドは30秒後に空の穴に戻ります。途中で抜けて戻ってきた人は、ラウンドが続いていれば元のフィールドに戻ります。
- **対戦**: 待機所の「対戦」看板か `/trigger versus set 1`（標準）/ `set 2`（ミニ）。同じ種類で2人そろうと、空いている2つのフィールドで**同時に**カウントダウンして始まり、先に100%にした人の勝ち（全員にチャットで発表、負けた側は「負け…」）。受付の取り消しは `/trigger leave`。片方が抜けたら相手の不戦勝。配信者を割り当てたフィールドは対戦に使われません。
- **記録**: 種類ごとに1人1つの自己ベストが残り、待機所のサイドバーに最速ランキング（10秒ごとに標準／ミニを切り替え）。`/trigger records` か「記録」看板で最速タイム・自己ベスト・対戦の勝ち数。フィールドの中のサイドバーは、そのフィールドの妨害ランキング。
- `/trigger lobby` でロビーへ戻れるのは今まで通り。

アバター表示用のリソースパックは、アプリが起動していれば入ったときに自動で配られます（なくても遊べます。アイコンが四角い記号になるだけ）。

## ルール
- 穴の中でホットバーのコンクリートパウダー（自動補充）を置いて埋める。置いたブロックは砂のように落ちて、着地した位置でブロックになるので隙間ができない。壁はガラスで壊れない。落下ダメージ・ダメージなし。
- `/trigger lobby` でロビーへ戻れる（lobby_return データパック、function-permission-level=3）。
- 100% になったらクリア。タイムと最速記録を表示し、15秒後に次のラウンド（そのフィールドだけ）。
- ボスバーに埋め立て％と経過時間、サイドバーに「妨害ランキング」（技を撃った回数）。どちらもフィールドごと。
- 技・支援は、そのフィールドの穴とそこにいる人だけに効きます（ほかのフィールドには影響しません）。
- 技は必ず「表面から下へ」削るので、埋められない穴は残りません。

## 技とギフト（初期設定。パネルの「ギフト」タブで変更可）

| コイン | 技（ランダム） |
|---|---|
| 1〜 | 太陽拳（目くらまし）/ ゴムゴムのピストル（吹っ飛ばし＋足元2個）/ 千鳥（周り1段） |
| 5〜 | 螺旋丸（足元3×3を4段掘る）/ 気円斬（上2段）/ 影分身の術（分身4体が20秒邪魔）/ 術式反転「赫」（上空へ吹っ飛ばす） |
| 20〜 | かめはめ波（上3段）/ 術式順転「蒼」（足元を6段掘って引きずり込む）/ 天照（黒い炎で2段）/ 霹靂一閃（2段） |
| 99〜 | 虚式「茈」（上8段）/ 領域展開「伏魔御廚子」（斬撃で穴だらけ）/ 尾獣玉（大爆発で6段） |
| 500〜 | 領域展開「無量空処」（8秒動けない・置けない＋4段） |
| 1000〜 | 元気玉（上12段） |

- ギフト名で固定: バラ→千鳥、TikTok→太陽拳、GG→ゴムゴム、指ハート→螺旋丸、ドーナツ→かめはめ波、ハンドハート→茈
- フォロー→花火、シェア→仙豆（穴を埋めて1段足す）、サブスク→みんなの応援（3段）、いいね500回ごと→仙豆
- 大技にはクールダウンあり（無量空処・元気玉30秒など。フィールドごとに数える）。その間は花火に置き換え。
- 演出はすべてバニラのパーティクル・効果音・コマンドで作っています（原作の画像・音声は使っていません）。

## 操作パネル（http://127.0.0.1:8790/）
- 「ライブ・テスト」: 全フィールドの一覧（種類・状態・％・時間・最速・プレイヤー・配信者と TikTok の接続・キュー）。各行で開始／停止／接続・切断、「選ぶ」で下の操作の対象を切り替え。
- 「操作するフィールド」: 新しいラウンド・一時停止・全員を待機所へ・ランキング消去・会場を作り直す・キュー消去。待機所だけ／全部の作り直しも。テストギフトと「アクションを直接実行」も選んだフィールドへ。
- 「記録」: 種類ごとの最速タイム上位と対戦の勝ち数。ログはフィールドで絞り込めます。
- 「接続設定」→「配信者とフィールド」: 1フィールドに1人。その TikTok のギフト・フォロー・シェア・いいね・コメントはそのフィールドだけに効きます。ギフトの割り当て・クールダウンなどの設定は全フィールド共通。
- 以前の config.json（`tiktokUsername` だけ）はそのままフィールド1の配信者として読み込みます。
- API: `/api/state`（fields[]）、`/api/game {cmd, field}`（field は番号・"all"、作り直しは "hub" も可）、`/api/test {field,...}`、`/api/tiktok {connect, field?}`、`/api/clear {field?}`、`/api/leaderboard`、`/api/overlay?field=N`。RCON では `function anime_live:f<N>/act/<技> {name:..,gift:..,rname:..}`（旧 `anime_live:act/<技>` はフィールド1）。

## 作り直し
- データパック: `cd tiktok-live\datapack` → `python build.py anime_umetate_datapack.zip` → サーバーを止めて `server\AnimeUmetate\datapacks` にコピーして起動（動いているサーバーの zip を上書きして `/reload` すると、試験鯖では読み込み中に落ちました）。`.actions.json` と `.fields.json` もアプリが読むので一緒に作られます。
- リソースパック: `python resourcepack\build.py`（作り直したら server.properties の resource-pack-sha1 を更新）
- 会場が壊れたら、パネルの「会場を作り直す」（フィールドごと）か「待機所を作り直す」。
- `tools\rcon-cli.mjs "コマンド"` でサーバーにコマンドを送れます。

## ボットでの試運転（開発用）
- `test-server\`: 本番と同じデータパックを入れた Paper 26.2＋ViaVersion/ViaBackwards のオフライン試験鯖（ポート 25592、RCON 25593）。`java -jar paper.jar --nogui` で起動。
- `node tools\playtest-bot.cjs 300`: 26.1.2 のボットが入ってパウダーを置き続ける（minecraft-server-dev の builder-bot の mineflayer を借りて動かす）。`RCON_DIR=test-server node tools\rcon-cli.mjs "function anime_live:act/kamehameha {name:\"t\",gift:\"t\",rname:\"t\"}"` で技を当てられる。
- `node tools\field-bot.cjs 名前 フィールド番号|vs1|vs2|hub [秒] [置く間隔tick]`: 待機所からフィールドを選ぶ（または対戦受付する）ボット。2体同時に動かして同時進行や対戦を試せます。`node tools\kiosk-bot.cjs 名前` は看板の右クリックと `/trigger records`・`leave` の確認用。
- 2026-10-05 の複数フィールド試験: Alice（F1）と Bob（F2）が同時に埋め立て。F2 にだけ茈を撃つと F2 は 83→2 個、F1 は 122→129 個と影響なし（メッセージも Bob だけ）。F1 がクリアしても F2 はプレイ中のまま。対戦（ミニ）は Carol（F5）と Dave（F6）が同じ tick にスタートし、先に埋めた Carol の勝ちが両方に発表。
