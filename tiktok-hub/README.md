# SharyTech TikTok Hub（全ゲームの TikTok LIVE 連携アプリ）

TikTok LIVE のギフト・フォロー・シェア・いいね・コメントを、SharyTech のマイクラゲームの演出に変えるアプリです。
前はゲームごとに別のアプリ（ディフェンス 8788 / クラロワ 8789 / アニメ埋め立て 8790 / ハロウィン 8787）でしたが、これ1つにまとめました。

```
TikTok LIVE（配信者ごとに1接続・何人でも同時）
   └─> このハブ ──> その配信者に割り当てたゲーム＋番号（フィールド／アリーナ）
                       ├─ RCON 25584 ─> TikTok Defense（銃MOD ディフェンス, 25574）
                       ├─ RCON 25581 ─> マイクラ版クラロワ（25580）
                       ├─ RCON 25591 ─> アニメ技の埋め立て（25590）
                       └─ RCON 25575 ─> ハロウィン・ナイト（play-server 25566）
パネル http://127.0.0.1:8800/   OBS http://127.0.0.1:8800/overlay?game=<ゲーム>&field=<番号>
```

## 起動
- `start-hub.bat`（初回は `npm install` を自動で実行。Node.js 20 以降が必要）。パネル http://127.0.0.1:8800/ が開きます。
- この PC では自動起動（`autostart\services.json` の `tiktok-hub`）。手で起動するなら `node src\index.js`（ログを残すなら `hub.log` に出す）。
- もう起動しているのに `start-hub.bat` を押した場合は「ポート 8800 を使えません」と出て終わります（パネルはそのまま使えます）。

各ゲームのパネルは `http://127.0.0.1:8800/g/defense/`・`/g/clash/`・`/g/anime/`・`/g/halloween/`・`/g/koma/` でも単独で開けます。

## ♟️ コマバトルRPG（Unity）
- マイクラではなく Unity のゲーム（プロジェクトは `C:\Users\kanek\3D koma RPG`）。RCON の代わりに、ハブが `ws://127.0.0.1:8810/` で待ち、再生中のゲームがそこへつなぎに来ます。概要ページの「サーバー」欄は「Unity（WebSocket 8810）」で、ゲームを再生していないと赤のままです。
- 配信者ページで配信者を「♟️ コマバトル」の盤1に割り当てると、その配信のコメント・いいね・ギフト・フォロー（サブスクも）・シェアがそのままゲームに届きます。何をどう強くするかはゲーム側（Unity）で決めています。
- ゲームがつながっていないあいだのイベントは最大 200 件・60 秒まで取っておき、つながったときに送ります。
- ゲームは 1 秒ごとに自分の状態をハブへ送り返し、パネルの「ゲームの様子」に出ます。
- オーバーレイ（`/overlay?game=koma&field=1`）はギフトのお礼だけ。ゲーム画面そのものは Unity のウィンドウを取り込みます。
- 中身は `src/games/koma/index.js`（WebSocket は `ws` パッケージ）。

## 📺 配信ツール（TikFinity にあるもの）
ゲームの演出とは別に、どの配信者にも効く配信の道具です（ゲームに割り当てていない配信者でも使えます）。設定は「📺 配信ツール」ページで全員共通、数（いいね・コイン・ランキング・チャットなど）は配信者ごと・LIVE ごとです。新しい LIVE（別の roomId）に接続すると 0 から数え直し、ハブを起動し直しても同じ LIVE なら続きから数えます（`state/live-sessions.json`）。

| OBS のブラウザソース | 中身 |
|---|---|
| `/live/alerts` | フォロー・シェア・サブスク・ギフト・いいね達成・入室のポップアップ＋効果音＋読み上げ。**コメントの読み上げもここから鳴る** |
| `/live/chat` | チャット欄（ギフト・入室も出せる） |
| `/live/events` | 最近のフォロー・シェア・サブスク・ギフト |
| `/live/goal?n=1` | ゴールの目標バー（`n` は上から何番目か。達成したら「次の目標」だけ上がる） |
| `/live/top` ・ `/live/likers` | ギフトのコイン・いいねのランキング |
| `/live/stats` | 視聴者・いいね・コイン・フォローのカウンター（`show=viewers,likes,coins,follows,shares,subs,gifts,joins,comments`） |
| `/live/timer` | 延長タイマー（コイン・フォロー・シェア・サブスク・いいねで延びる。パネルでスタート・一時停止・±） |
| `/live/wheel` | ギフトルーレット |

- URL のうしろに `?game=<ゲーム>&field=<番号>`（その番号にいる配信者に自動で切り替わる）か `?user=<TikTok の ID>` を付けます。パネルの右側に配信者ごとの URL が出ます。共通で `size=1.5`（大きさ）・`bg=1`（黒い背景）・`max=`（行数）、alerts は `sound=0`・`tts=0` で音を消せます。
- 読み上げの声は Windows の声（SAPI、この PC は Haruka）・VOICEVOX（起動中のエンジン 127.0.0.1:50021 の API。人ごとに声を変えることもできる）・ゆっくり（AquesTalkPlayer.exe をコマンドラインで呼ぶ。個人の非商用のみ無料）・ブラウザの声から選びます。VOICEVOX やゆっくりが使えないときは Windows の声で読みます。読み上げは wav を作り、alerts のオーバーレイが鳴らします（OBS の「OBS で音声を制御する」で音量を調整）。Windows 以外ではブラウザの声で読みます。絵文字は読まず、URL は「URL」、同じ文字の連続は 3 つまで。読まない言葉・頭が `!` のコメント・フォロワーだけ・同じ人の間隔・ためておく数を決められます。
- 効果音は最初から 7 つ（チャイム・コイン・ファンファーレなど、ハブが作る音）＋自分の mp3/wav/ogg/m4a を足せます（`state/sounds/`）。
- 🎡 ギフトルーレット（`/live/wheel`、`hide=1` で回っていないときは隠す）: 決めたギフトかコイン以上で回り、止まった項目の文を出して読み上げる。項目にゲームのアクションを付けると、その配信者のゲーム・番号でそのアクションが起きる（各ゲームの `runAction`）。
- 🎁 ギフトごとのアラート: 決めたギフトだけ別の文・効果音・画像／GIF／動画（`state/media/`、png/jpg/gif/webp/mp4/webm）。種類ごとのアラートにも画像・動画を付けられる。
- ⚡ 高額ギフトの割り込み: 決めたコイン以上のギフトは、アラートとゲームのアクションのキューで先頭に入る（各ゲームの `enqueue` → `pushQueued`、`ctx.firstCoins()`）。
- 📁 プリセット（「🎁 ギフト一覧」ページ）: ギフトの割り当てに名前を付けて保存し、配信中に配信者へ切り替える（`config.json` の `presets.<ゲーム>`、`/api/presets`）。
- 中身は `src/core/live.js`（設定は `config.json` の `live`）と `public/live.html`（全部のオーバーレイ）。オーバーレイは `/api/live/stream`（server-sent events）で受けます。

## 配信者の割り当て
- 配信者 = **TikTok の ID ＋ Minecraft の名前**。「配信者」ページで追加し、**ゲーム**と**番号**（ディフェンス・埋め立て・ハロウィンはフィールド、クラロワはアリーナ）を選びます。
- その配信のギフトなどは**そのゲームのその番号だけ**に届き、**そのゲームのギフト設定**（ギフト名の割り当て・コインの段階・クールダウンなど）で演出に変わります。何人でも同時に接続できます。
- ゲームを変えるとその場で切り替わります（TikTok はつないだまま）。1つの番号には1人。別の人を入れると前の人は「割り当てなし」になり、接続も切れます。
- 「オン」を外すと TikTok には接続しません（割り当ては残る）。
- Minecraft の名前は各ゲームで使われます: ディフェンスは「配信者をこのフィールドに入れる」と待機所の表示、クラロワは AI 対戦を始める人、埋め立ては入ると直接そのフィールドへ。
- 各ゲームのパネルの「配信者／TikTok の ID／マイクラ名」の欄で変えても、配信者ページに反映されます（どちらで変えても同じ）。
- 「テスト」ボタンは、その配信から1コインのギフトが来たときと同じ流れで演出を出します（リハーサル用）。各ゲームのパネルのテストギフトも今まで通り使えます。

## 配信者ごとのギフトの割り当て
- 「🎁 ギフト一覧」で配信者とゲームを選び、ギフト名で決めるアクション・コインの段階・フォロー/シェア/サブスク/いいねを変えて「この配信者の割り当てとして保存」。その配信者の配信（とその番号へのテストギフト）だけに効きます。
- 決めていない配信者・ゲームは、そのゲームのパネルのギフト設定（今まで通り）を使います。「ゲームの設定に戻す」で消せます。割り当てはゲームごとに別々に覚えるので、ゲームを切り替えても残ります。
- ギフト名は TikTok が視聴者のアプリの言語で送ってくるので、日本語と英語の両方（例: バラ, Rose）を入れておきます。
- ギフトの画像と値段は TikTok の公開のギフト一覧（約670種）から取り、`state/gift-catalog.json` と `state/gift-img/` に取っておきます（起動時と1日ごとに読み直し。配信で届いたギフトの画像も足す）。「＋ 画像からギフトを選ぶ」で絵を見て選べます。
- 保存先は `config.json` の `streamers[].rules.<ゲーム>`。コマバトルは Unity 側で決めるので対象外です。

## OBS
- ブラウザソースに `http://127.0.0.1:8800/overlay?game=<ゲーム>&field=<番号>`（1280×720、背景は透明）。ゲームは `defense` `clash` `anime` `halloween`。配信者ページと概要ページに各番号の URL があります（「URLコピー」）。
- ギフト一覧（透過の画像）: `http://127.0.0.1:8800/gift-list?game=<ゲーム>&field=<番号>`。その番号の配信者の割り当てを数秒ごとに読み直して描きます。`w=`幅（560）・`size=`文字（22）・`bg=0`（黒い背景なし）・`tiers=0`（コインの段階を出さない）・`other=0`（フォローなどを出さない）・`title=`見出し。URL は「🎁 ギフト一覧」ページで作れます。
- 例: クラロワのアリーナ2 → `http://127.0.0.1:8800/overlay?game=clash&field=2`、埋め立てのフィールド3 → `...?game=anime&field=3`。

## 前のアドレス（互換）
OBS のソースやサーバーのリソースパックの URL を変えなくて済むよう、ハブは前のポートでも同じものを出します。

| ゲーム | 前のアドレス（そのまま使える） |
|---|---|
| ハロウィン | `http://127.0.0.1:8787/` ・ `/overlay` |
| ディフェンス | `http://127.0.0.1:8788/` ・ `/overlay?field=N` |
| クラロワ | `http://127.0.0.1:8789/` ・ `/overlay?arena=N` ・ `/resourcepack.zip`（server.properties が指している） |
| アニメ埋め立て | `http://127.0.0.1:8790/` ・ `/overlay?field=N` ・ `/resourcepack.zip`（server.properties が指している） |

前のアプリがまだ動いていてポートが使われていると、そのポートは取れません（ログと「設定」ページに表示）。ハブは30秒ごとに取り直すので、前のアプリを止めれば自動で切り替わります。
前のアプリが管理者で動いている場合は、PC の再起動か、管理者の PowerShell で `Get-NetTCPConnection -LocalPort 8790 -State Listen | % { Stop-Process -Id $_.OwningProcess }` で止めてください。
（ポートは各ゲームのパネルの「パネルのポート番号」で変えられます。ハロウィンを単独配布のアプリで動かすときは、ハブの「設定」でハロウィンを外してください。）

## 設定ファイル
- `config.json`（初回起動で作成）: `hubPort`（8800）、`signApiKey`、`streamers`（配信者）、`games.<ゲーム>`（各ゲームの RCON・ギフト設定など。前の各アプリの config.json と同じ形）、`disabledGames`。パスワードが入るので配らないこと。
- 初回起動時、隣にある前のアプリの `config.json`（`tiktok-defense\app`、`clash-royale-mc\tiktok-live`、`anime-umetate\tiktok-live`、`halloween-map\tiktok-live`）から RCON・ギフト設定・配信者を読み込みます。ディフェンスの記録（records.json）は `state\defense-records.json` に引き継ぎます。
- ゲームセット（配布の zip）では `kit.json` のサーバーフォルダの `server.properties` から RCON のポートとパスワードを読みます。
- データパックの情報（アクション一覧など）は、隣にゲームのフォルダがあればそこの最新を、なければ `data\<ゲーム>\` の同梱分を使います。

## しくみ（開発メモ）
- `src/core/`: TikTok 接続（`tiktok.js`、配信者ごとに1接続。イベントは届いた時点の割り当て先へ）、イベント→アクション（`events.js`）、アイコンのドット絵（`avatar.js`）、RCON（`rcon.js`）。
- `src/games/<ゲーム>/`: 前の各アプリの処理をそのまま移したもの（キュー・クールダウン・フィールドの読み取り・ランキング・作り直し・対戦など）。`games/<ゲーム>/panel.html`・`overlay.html` は前のパネル（API の URL を相対パスにしただけ）。
- API はゲームごとに前と同じ: `/g/<ゲーム>/api/state`・`/api/test`・`/api/game`・`/api/config` など（旧ポートでは `/api/...`）。ハブ全体は `/api/status`・`/api/streamers`・`/api/settings`。POST にはヘッダー `X-HL-Panel: 1` が必要。
- パネルは自分の PC（127.0.0.1）からしか開けません。
- 前の各アプリ（`*\tiktok-live`、`tiktok-defense\app`）は消していません（使われなくなっただけ）。
